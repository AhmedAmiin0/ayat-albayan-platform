# CLAUDE.md — Ayat Al-Bayan Academy Platform

Arabic-first (RTL) platform replacing Google Forms/Sheets/Calendar/Apps Script for an online Quran academy: WhatsApp lead inbox → student registration → teacher assignment & scheduling → lesson reports (PDF to parents via WhatsApp) → subscriptions, payments, teacher payouts.

- `docs/02-issues.md` — 30+ concrete defects (each maps to a requirement ID)

## Stack (do not substitute)
Turborepo + pnpm · Supabase (Postgres, Auth, Storage, pg_cron/pg-boss) · NestJS (Fastify) API · React 19 + Vite + TanStack (Router/Query/Table/Form) + Tailwind/shadcn web · Expo (expo-router) admin mobile · Meta WhatsApp Cloud API · Playwright (web e2e) · Vitest/Jest unit · jest-expo mobile.

## Hard code rules (CI fails otherwise)
1. **Max 150 lines per file** (`max-lines`, blank lines & comments count) of **≤ 100 characters** (`max-len`; long strings and URLs may run on), functions ≤ 50 lines (`max-lines-per-function`, tests exempt). Split: `x.service.ts` / `x.repo.ts` (class `XRepo`: the only place that injects `DB`) / `x.mapper.ts` / one component per file / tests split by scenario. **No new `*queries.ts` file or `class XQueries`** (`pnpm guard:queries`; the old ones are listed in `refactor/guards/queries.json` until lane R renames them, docs/32 D2). Components call the API through hooks, never `apiFetch`/`apiSend` in a `.tsx`.
2. **Max 3 parameters per function, 4 per constructor** (`ab/max-params`, docs/32 D1; method signatures count). Use a typed options object for the 4th+.
3. Strict TypeScript, no `any`, no non-null assertions in app code. Type-aware lint at `--max-warnings 0`, React 19 idioms (mobile), no `useMemo`/`useCallback`/`memo` where the React Compiler builds (web, mobile), effects only in named hooks: `docs/31a-strict-types-lint.md`. Oxlint, type-aware via tsgolint, is the only linter (`pnpm lint`, warnings denied; `docs/31b-oxlint-mapping.md`); formatting is oxfmt. **No suppressions**: no disable or ignore comments, no `@ts-` escapes, no cast or rename made only to quiet a rule, no rule switched off or loosened, and no new baseline entry; fix the code. `oxlint-suppressions.json` is the only baseline: its entries are old debt being removed (`docs/59-no-suppressions.md`); `pnpm guard:lint` fails on any count above the base branch's, per file and per rule, and on a new entry or file. Fixing an old one still needs its prune commit: commit the `oxlint-suppressions.json` diff the red CI lint job prints («Oxlint baselines to prune»), or run `pnpm lint:prune` in a cloud session, never on the owner's PC. A workspace whose suppressions file is gone never gets one back. A package's own rules live in its `lint.blocks.mjs`; the repo's own rules are `ab/*` JS-plugin rules in `packages/config`.
4. Every PR/commit adds unit tests next to the code, or in the unit folder's tests/ when it has 2+ (`*.test.ts`). Pure logic (phone/arabic normalisation, occurrence generation, conflict check, state machines, balances, reminder timing) must be unit-tested ≥ 80 %.
5. Playwright e2e for the six journeys in `docs/03-requirements.md §5`; run in CI against the Supabase stack the runner starts (ci.yml «Start local Supabase») + WhatsApp stub (`tools/wa-stub`).
6. All times UTC in DB; tz on every person; never free-text times.
7. Phone numbers E.164 only; `students.code` (`AB-nnnn`) is generated, never typed.
8. Idempotent jobs (dedup keys); idempotent occurrence generation (`unique(rule_id, starts_at)`).
9. RLS on every table + guards in Nest. Secrets only via env/Vault.
10. Arabic UI strings in `packages/shared/i18n/ar.json`, written in clear Modern Standard Arabic (owner, 2026-10-03: no Egyptian dialect); keep the domain vocabulary below.
11. Few `if` conditions (owner, 2026-11-01): prefer lookup tables / `Record<Key, Handler>` maps and per-kind strategies over if/else or switch chains, named predicates over inline boolean logic; at most one early-return guard where possible, never nested ifs, no nested ternaries, no lonely `if`, no `else` after `return` (`max-depth` 2; `complexity` 8, 6 in plain `.ts`: packages/config/eslint-flow.js).
12. Validate with **zod** (owner, 2026-11-01: «use zod»): every API body/query/param, env and DB config value, webhook payload, external API response and form is parsed with a zod schema (shared ones in `packages/shared`), and types come from `z.infer`; no hand-written `typeof`/`in`/shape checks or manual type guards for data that crosses a boundary. Reuse, never re-declare (owner 2026-11-21): primitives (`id()`, `phoneE164`, `timeZone`, money, page) from `@ab/core/schemas`, contracts in `packages/shared/src/<domain>/x.schemas.ts`.
13. **Imports only through a module's `index.ts`** (api `modules/<domain>/<module>`, web `features/<domain>/<feature>`, mobile `src/<feature>`), **written absolute** in apps: `@/…` (→ `src/…`), never `../` (`ab/no-parent-imports`; `./` siblings stay; `pnpm imports:absolute -- <files> --write`; owner 2026-10-30, docs/32 R12); ≤ 12 code files and ≤ 12 sub-folders per folder; no new duplicate (jscpd) or unused code (knip). The `refactor/folder-cap/` and `refactor/guards/` baselines are old debt: an entry never rises, and no new entry or file is added (`pnpm guard:baselines`, docs/04 §8). Shared web + mobile logic lives in `packages/client-core`.
   A unit with 3+ files (code, props, types, tests...) lives in its own folder with index.ts; its tests go in tests/ when there are 2+. In apps/api each feature folder with a controller is its own Nest module.

Rules 14–24 (owner 2026-11-21/22, `docs/57-code-quality-rules.md`): a rule's CI check turns on only when the code already passes it (docs/57 §9); until then review holds new code to it.

14. **TDD** (R14): red → green → refactor for every behaviour; write the failing test first and run it; test failure paths and edges, not only the happy path; never weaken, skip or delete a test to get green (`test.skip(cond, 'reason')` only; no `.only`); each PR body lists «behaviour → test». Changed logic files: ≥ 90 % lines / 80 % branches (CI coverage job). Money, schedule, status, phone/arabic and reminder logic also get mutation tests (Stryker).
15. **Types apart from logic** (R1): a file with runtime code exports no types; types go in `x.types.ts`, a schema's `z.infer` type stays in its `x.schemas.ts`; types used by two apps or by api + a client live in a package (`@ab/shared` or its domain package), never copied.
16. **Components** (R2–R5): a `.tsx` file defines ONE component and nothing else; its props live in `Name.types.ts`; both are exported from the folder's `index.ts` (`Name.tsx`, `Name.types.ts`, `Name.test.tsx`, `index.ts`). A reusable or UI component lives in `packages/web-kit` (web) or `packages/mobile-kit` (React Native), never in an app; logic both platforms share lives in `packages/client-core`.
17. **Design system** (R15): tokens have one source (`packages/catalog/src/theme`; web CSS is generated from it). Apps use kit components and tokens only: no hex/rgb colours, no Tailwind arbitrary values (`text-[13px]`, `bg-[#…]`, `z-[…]`), no `dark:` variants, no raw `<button>`/`<input>`/`<select>`/`<textarea>`/`<a>` (web) or `Pressable`/`TextInput` (phone), no raw numbers in RN styles. A new kit component comes test-first with `Name.showcase.tsx` (states, RTL/LTR, dark, reduced motion, 44 px target, a11y role/label) and a design review (skills above).
18. **Builders and adapters** (R8): tests build data with builders (`x.builder.ts` in the owning package's `testing/`: `aLesson().held().build()`), not hand-written rows. Every outside service or platform difference sits behind a port (`x.port.ts`) with implementations `x.<impl>.adapter.ts` and a `x.registry.ts`; only an adapter imports the SDK (Stripe, S3, LiveKit, Expo native).
19. **Fast and scalable** (R9, R10): no `await` on the DB inside a loop or `.map(async)` (batch with `.in()`/`readChunked`/an RPC); explicit column lists (no `select('*')`); bounded reads (`.range`/keyset; `readAll` only in jobs); index what you filter (check with EXPLAIN in CI). Clients: query keys only from a key factory (`x.keys.ts`), one `queryOptions` per endpoint in `packages/client-core`, a sane default `staleTime`, virtualised long lists (`LazyList`, TanStack Virtual).
20. **Events, not polling** (R11): a write emits a typed domain event (catalogue `packages/shared/src/events`, zod payloads with ids only, outbox + dedup key); other modules react in `x.listener.ts`; clients get it over Realtime and invalidate keys / update stores from one map in `client-core`. Polling only where an event cannot work (a server that is down, a missed-webhook catch-up), with a `// poll: <reason>` comment.
21. **React 19 compiler and state** (R12, R13): no `useMemo`/`useCallback`/`memo`; no `useEffect` for derived state, events, fetching or resets (compute in render, handler, TanStack, `key`); the rest live in named shared hooks. Client state only in zustand v5 (`createStore` in `packages/client-core/src/<domain>/x.store.ts`, thin selector hooks, `persist` through a storage adapter); server data only in TanStack Query, never copied into a store; no hand-made `useSyncExternalStore` stores.
22. **Server time** (R16, owner 2026-11-21: «use the server time and format it in the client side»): «now», today, windows and every date rule are decided on the server (UTC instants; an endpoint that needs «now» returns `server_now`); clients only format instants in the viewer's tz with the shared `packages/time` formatters, never `Date.now()`/`new Date()` for a business decision (UI timers and animation only).
23. **Apps and packages stay apart** (owner 2026-11-22: «apps cannot import logic from each other and make the packages not depending on each other as much as possible»): an app never imports another app (code, types, assets or config); logic two apps need moves into a package. Packages form one layered graph with the fewest edges: a package depends only on packages below it, never on an app, never in a cycle; a package does not re-export another package (no facades); domain packages (time, money, schedule, settings, catalog, i18n) depend on `@ab/core` at most; schedule and money may also use `@ab/time` and `@ab/catalog` (owner 2026-11-22), not on `@ab/db` or each other (pass data or a port in instead). Every new package edge needs a reason in the PR. `pnpm guard:packages` checks every PR against its base branch: layers and allowed edges live in `refactor/guards/packages.json`, and a new extra edge, a new re-export or a new `@ab/db` import outside the api's repos fails; a PR that widens that table prints a warning and merges only with the repository owner's go (owner 2026-11-22: no required code review).
24. **Comments only when they add value** (owner 2026-11-22: «dont add any useless comments, remove all useless comments that add no value to the code»): a comment explains why, never what: a non-obvious constraint, the business rule and the doc it comes from (`docs/NN §x`), the cause of a workaround, a money, security or time invariant, or a public contract the types cannot express. Never: restating the code or its name, obvious steps, dates, owner quotes or history (they belong in the PR or `docs/`), tool mentions, commented-out code, decorative separators, a TODO without an issue. When a dated owner quote carries a rule, keep the rule in one plain line and drop the date and quote. Old comments are removed in comment-only PRs (branch `chore/comments-*`) whose code `pnpm guard:comments` proves unchanged.
25. **Angular commits** (owner 2026-11-24): every commit message and PR title starts with the header `<type>(<scope>): <subject>`, at most 100 characters. Types: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`, `revert`; `style` only for formatting that changes no meaning. A move or rename-only PR is `refactor`; a comment-only PR is `docs`. The scope is a workspace short name (api, staff-web, family-web, staff-mobile, family-mobile, db, shared, client-core, web-kit, mobile-kit, core, time, money, schedule, settings, catalog, i18n, config, e2e, tools), or `repo` or `deps`, or a module inside a workspace (`fix(api/booking): …`). The subject is imperative, starts lower case and has no trailing period. The body says why; footers are `BREAKING CHANGE: …` and `Closes #n`. A squash merge's subject is the PR title plus ` (#n)`, so the title must already follow the rule. Workflow `pr-title` fails a PR whose title breaks it, and lane-automerge skips one (`tools/scripts/ci-checks/lint/commit-header`); there is no exception list.

## How to execute (speed)
- Use the **Workflow** tool for every phase with ≥ 3 independent modules (owner opted in). Builders in worktrees → verifiers → integrator (see `docs/05-build-plan.md §2`). ≤ 10 agents per run.
- Every agent prompt repeats rules 1–4 and lists the requirement IDs it must satisfy.
- Project skills live in `.claude/skills/` (see its README): every design review loads `heuristic-evaluation`, `design-qa-checklist` and `critique-brand-consistency`; every migration, SQL or RLS change loads `supabase-postgres-best-practices`.
- Before finishing any phase: the PR's GitHub Actions CI is green (lint, typecheck, test, e2e), watched with `gh pr checks <n> --watch` (failures: `gh run view <run> --log-failed`); write `PHASE_SUMMARY.md`.
- Tests, lint, typecheck, builds, installs (`pnpm i`), Supabase, docker, expo and dev servers never run on the owner's PC (owner, 2026-11-01: «run test with github actions or in the cloud»). Verify in GitHub Actions CI, or in a cloud session, which may run lint, typecheck and unit tests itself; e2e and DB checks run only in CI. Where the data import runs is still open (see Commands).
- **No AI mentions in git** (owner, 2026-11-22): commit messages, PR titles and descriptions, branch names and code comments never mention Claude, AI, an assistant, a model or a generation tool. No `Co-Authored-By` trailer for a tool, no «Generated with …» footer, no session links. A squash merge sets its own clean subject and body: the subject is the PR title plus ` (#n)` (rule 25), e.g. `gh pr merge 930 --squash --subject 'ci(repo): enforce angular commit messages and pr titles (#930)' --body …`.

## Commands (never on the owner's PC; where each one runs is on its line)
```
pnpm i                         # CI or a cloud session
pnpm supabase start            # local stack (packages/db): CI only (ci.yml e2e job)
pnpm turbo dev                 # api :3000, web :5173, wa-stub :4010: no remote place to run (the e2e job starts its servers through Playwright webServer)
pnpm lint && pnpm turbo typecheck test # CI or a cloud session (lint builds the packages first; the rest with their ^build)
pnpm turbo e2e                 # playwright (apps/staff-web against seeded db): CI only (ci.yml e2e job)
pnpm --filter staff-mobile start # expo: no remote place to run; mobile is verified by CI «test mobile»/«bundle mobile» and mobile.yml
pnpm migrate:dry && pnpm migrate:apply   # tools/migrate: follows tools/migrate/RUNBOOK.md until the owner decides
```

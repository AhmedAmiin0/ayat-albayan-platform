# 16 — Sales double role (sales + classroom assistant)

Owner, 2026-10-11: «sales should be able to see all chats and see the confirmed subscriptions they made
with their history», «also they should be able to see teachers students and current running sessions»,
«sales are playing double roles here: sales and assistant role».

The base role `sales` (shown «المبيعات», PR #74) keeps everything it had and also does the classroom
assistant's job across the academy. Smallest change: reuse the inbox, the classroom join and the
assistant's session row; new read-only routes under `/sales` with whitelisted columns.

## Decisions

### Already-started packages (row 24, «بدأ الاشتراك سابقًا»)

No backfill: nothing is generated or rewritten for a past start. `SubscriptionCreator` stores `starts_on` as given (status `unpaid`, `renews_on` null on the sales path) and recomputes as for any package. Lessons come only from schedule rules and bookings, never from a package. The balance (`v_subscription_balance` / `v_package_lessons`) counts the student's chargeable, held, non-trial, non-makeup lessons dated on or after `starts_on`, packages in `starts_on` order: so a back-dated package takes the lessons the student already had on the platform since that day, and its remaining count can start low (or at zero). An old student who studied before the platform has no lessons here for that time, so nothing is counted for it; when the package is used up, the usual rule (docs/11 §7, `pending_renewal`) applies. If some lessons taken before the platform must count, the admin records that with the existing tools (the package's lesson count or an adjustment), as today.

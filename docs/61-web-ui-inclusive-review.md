# 61 — Web UI review, pass 2: inclusive design and design system

Second pass of the web UI review of apps/staff-web (admin, sales, teacher, assistant) and
apps/family-web (guardian). Pass 1 covers heuristic-evaluation, design-qa-checklist and
critique-brand-consistency (docs/60, issue «Web UI review»); this pass adds the lenses below and
does not repeat pass 1. Review only: no UI code changes.

## How it was done

- Source: `develop` at the merge of #929, all routes in both `routeTree.gen.ts` files, the web-kit
  and `packages/catalog/src/theme`. Six reviewers, one per lens group, each working from the
  skills in `.claude/skills/` named in its section.
- **Screenshots were not used.** The «ui screens» run 45287856506 on `ci/ui-screens` succeeded, but
  its `ui-screens` artifact could not be downloaded into the review environment. Every finding
  therefore cites code (`file:line`), and the «Variant» is the breakpoint or theme the code applies
  to. The screenshot file is added to each finding when it is re-checked (§9).
- A second reviewer re-checked every critical and major finding against the code: 19 confirmed,
  26 downgraded, none dropped. Duplicates across lenses were merged (merged IDs in brackets).
- Ranking: opportunity score = severity (3/2/1) × 3 × reach (1.5 when the fix is shared) ÷ effort
  (S 1, M 2, L 3).

# 66 · Staff portal round 2: one list per view, tabs, charts

Two reviews of apps/staff-web on 2026-11-28 (the owner: too many lists on one page, scroll boxes inside scroll boxes; add tab bars and charts; review the portal). Items already in docs/65 are not repeated here: a row that extends one names it. Kit pieces added here are also used by family-web, so they stay customer-neutral.

## 1. The layout rule

Every staff view shows one primary list and has one vertical scroll area: the page. Vertical and horizontal scrolling are judged separately.

1. ONE LIST PER VIEW. A second list, table, feed or card grid goes into a kit Tabs + TabPanel, keeping the tab in the URL as `?tab=` (a zod enum in the route's validateSearch, the same way as `page-search.ts` on /admin/settings/communications). It can instead move to its own route or open on demand in a Drawer or Dialog. KPI rows, a short summary line or a 3-row banner count as chrome, not lists.

2. ONE VERTICAL SCROLL AREA. On a phone (<640px) and on short windows (<640px high), only PageFrame's `[data-page-scroll]` scrolls and every list flows inside it. On a desktop list page, the single fill box (DataTable `fill` / TableBox) is the only scroller: it takes the frame height left after head, toolbar and pager, the header row stays pinned, and the frame itself does not overflow. A page with no fill box scrolls only in the frame. No `max-h-* overflow-y-auto` box goes inside the page, inside a dialog body or inside a drawer. No scroll area sits inside another one.

3. HORIZONTAL. A wide table scrolls sideways inside its own ScrollX or table box, never the frame or the document (the responsive probe already asserts this). Tab strips and chip rows may scroll sideways. A table that would need sideways scrolling on a phone uses DataTable `stacked`.

4. EXCEPTIONS are listed in `exceptions`, and the guard reads them from one list. They are two-pane chat and the video room (a list pane beside a log, inside fixed chrome), the admin side nav, and modal overlays (exactly one scroller each). Anything else fails the guard.

### Exceptions

- Two-pane chat (/admin/inbox, /sales/inbox, /teacher/inbox, /teacher/messages): the thread list pane (paneScroll, rail.ts:17) and the message log each scroll beside fixed chrome. From @3xl/thread (a window of about 1458px or wider on admin) the lead/family panel scrolls as a third column (railThread). Below that it opens as ThreadSideSheet. Reason: a chat keeps its place in the list while the log scrolls, as WhatsApp does. The frame itself does not overflow there.
- Video room (/classroom/$lessonId, /meeting/$id): ParticipantGrid, the RoomStage strip and the RoomPanel chat or people pane each scroll inside a viewport-high room. Reason: it is a live call layout, not a page.
- Admin side nav (AdminLayout.tsx:46, from 900px): its own column beside the frame, never nested. Reason: fixed navigation chrome.
- Modal overlays: Dialog (dialog-classes.ts body :34/:51/:75; the overlay never overflows because the card's max-h equals the overlay padding) and Drawer (Drawer.tsx:40) are exactly one scroller each, with nothing inside them scrolling on its own. ForwardDialog's chat list and the CreateSubscription and CreateLink pickers flow in the body. Reason: transient and modal, and they cover the page.
- Transient popovers: the desktop bell NotificationPanel (max-h popover), ReplyOptions saved replies above the composer, and the more-menu or TeacherPicker dropdown outside dialogs. Reason: they close on outside press and never stay on screen beside a list.
- Phone composer (below shell): ComposerPhone's max-h-[70dvh] scroll keeps the send button above the keyboard while a long draft or template form is open. Reason: the viewport is shorter than the form.
- Horizontal only: ScrollX regions and a table's own x-scroll for wide tables, Tabs strips (tabs.tsx:101), SegmentedControl and RadioChips rows. Reason: sideways scrolling of one strip never creates a nested vertical scroll and keeps the frame from widening (the existing responsive-dashboard probe).

### The guard

Two checks that run in CI. Both are added in batch 6, once every route passes (docs/57 §9). Neither adds a baseline file.

(1) Static: `pnpm guard:scroll` (tools/scripts/ci-checks/lint/scroll/gate.mjs + run.mjs + tests/gate.test.mjs), added to package.json guards and the ci.yml lint job. It reuses the components gate's scanner and route resolver (tools/scripts/ci-checks/lint/components/find.mjs, routes.mjs, tree.mjs). It reads every class string (className literals, cn()/clsx args and exported string consts such as tableBoxClass or paneScroll) in apps/staff-web/src and packages/web-kit/src and reports three things:
(a) Any token, with any variant prefix, matching overflow-auto, overflow-y-auto, overflow-scroll or overflow-y-scroll, or a max-h-* in the same string as an overflow token, unless the file is in the gate's own EXCEPTIONS map (file → reason: PageFrame SCROLL, AdminLayout nav, dialog-classes, Drawer, rail.ts paneScroll/railThread and their importers InboxPage and TeacherMessagesPage, MessageLog, ComposerPhone below-shell, room/*, NotificationPanel popover, ReplyOptions). overflow-x-auto and ScrollX pass.
(b) For each route file, the page tree that renders more than one DataTable `fill` or non-`center` `<TableBox`, unless each sits in a different TabPanel branch.
(c) An import of paneScroll or railThread outside the EXCEPTIONS files.

(2) Runtime: e2e/tests/platform/scroll-areas.spec.ts in the ci.yml e2e job (desktop project, sets its own viewports, modelled on responsive-dashboard.spec.ts). It seeds rows so the lists overflow (seedDashboard plus the existing finance and people helpers). For each staff route per role (admin, teacher, sales; ar and en) at 1440x900, 1280x720 and 390x844 it evaluates the following. inner = elements under [data-page-scroll], outside [role=dialog], whose computed overflow-y is auto or scroll and whose scrollHeight > clientHeight + 1. frame = [data-page-scroll] scrollHeight > clientHeight + 1.
It asserts:
- at 390px, inner.length === 0;
- at desktop, inner.length + (frame ? 1 : 0) <= 1, and no inner element has another scrolling ancestor, except on the routes in the same EXCEPTIONS list, where the list pane and log are allowed but nesting is not;
- document.querySelectorAll('[data-table-box]').length <= 1;
- the frame and the document have no sideways overflow.
A new route or component that adds a second scroller or a second fill list fails one of the two.

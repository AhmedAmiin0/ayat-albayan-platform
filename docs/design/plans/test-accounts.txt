TEST ACCOUNTS (owner 2026-11-17)

Owner words: «if the user have flag called test can pass some security validations».
Owner's choice of what a test account may skip: watermark, rate limits, live join window, screen-capture block.

SAFETY MODEL (non-negotiable)
- Double condition: a check is skipped only when the signed-in profile is_test AND the content's student is_test.
  The one exception is rate limits, which have no student context: the profile flag alone applies.
  So a test flag set on a real account by mistake opens nothing on real families' data.
- Never skippable: sign-in/auth, scope (who sees which student), RLS, admin permissions, payments.
  Test accounts get NO extra visibility.
- The server decides from the database, never from anything the client sends or from editable JWT claims.
- Family links: a test family profile (guardian or student login) can link only to test students, and a real one only to real students. Enforced in the DB with triggers on the link tables (guardian↔student, a student's own profile).
